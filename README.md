# koishi-plugin-huaji-xiuxian

群聊修仙文字 MUD，由 [nonebot-plugin-xiuxian-2](https://github.com/luolianxiyou/nonebot-plugin-xiuxian-2) 移植并重构为 Koishi 插件。

当前版本：**0.6.2**

## 依赖

| 服务 | 必需 | 说明 |
|------|------|------|
| `database` | 是 | 玩家、背包、宗门等数据 |
| [monetary](https://koishi.chat/market?keyword=monetary) | 是 | 灵石经济 |
| [markdown-to-image-service](https://www.npmjs.com/package/koishi-plugin-markdown-to-image-service) | 否 | 长文本转图片（可选，基于 Puppeteer，已内嵌中文字体） |

## 快速开始

1. 在 Koishi 控制台启用本插件
2. 发送 **我要修仙** 创建角色
3. 发送 **修仙帮助** 查看指令

## 0.6.1 更新摘要

### 坊市补货与容量优化

- 神秘人补货改为**按需上架**：坊市全部商品数低于阈值时才自动补货，避免列表无限累积
- 坊市新增**容量上限**，达到上限后禁止玩家/系统上架（提示「坊市货架已满」）
- 坊市物品**超过时限无人购买自动下架**，玩家物品发回背包（上架时即提示）
- 新增三个可配置项（见下表）

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `shopRestockThreshold` | `5` | 神秘人补货阈值：商品数低于该值才补货 |
| `shopCapacity` | `30` | 坊市容量上限 |
| `shopExpireHours` | `72` | 物品过期小时数，超时自动下架 |

## 0.6.2 更新摘要

### 群聊白名单与黑名单

控制台「基础设置」新增四项，限制机器人仅在指定群游玩：

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `groupWhitelistEnabled` | `false` | 群聊白名单开关 |
| `groupWhitelist` | `[]` | 白名单 QQ 群号列表（纯数字）。开关开启时生效；**列表为空则所有群均不响应** |
| `allowPrivateChat` | `false` | 白名单开启时是否也响应私聊（默认仅响应白名单群） |
| `userBlacklist` | `[]` | QQ 号黑名单：列表中的用户无论私聊/群聊均不响应（无需开启白名单即生效） |

行为要点：

- 开启白名单后，**仅在白名单群内的消息会得到响应**；非白名单群与（默认）私聊一律**静默忽略**（不回复任何消息）
- 群号按「去除平台前缀后的数字」匹配（如 `qq:123` 与 `mock:123` 均视作 `123`），便于跨平台与测试
- **管理指令（`authority >= 999`，如 系统坊市上架、重置状态、创建世界boss、神秘力量）豁免白名单**，仍可在任意群执行，但同样受黑名单约束
- **定时任务（坊市自动补货、过期下架）仅处理白名单内群**，移出白名单的群不再被自动维护

## 0.6.0 更新摘要

### 洞天经营玩法

- **开辟洞府**：耗灵石开辟个人洞府（可自定义名称，缺省自动命名），自动获赠灵田 1 块
- **灵气升级**：耗灵石提升洞府灵气等级（1~5 级），每级提升闭关修为收益与成熟收成
- **灵田种植 / 灵田收获**：消耗背包 1 份药材种到空闲灵田（交互选序号），越稀有成熟越久；收获按灵气等级随机获得 2~8 份（不凭空得药材）
- **开垦灵田**：耗灵石扩建灵田，第 2 块 100 万、之后每块翻倍，上限 999 块；种植自动填入第一块空闲灵田
- **灵田情况**：查看各块灵田的种植与成熟状态
- **洞府信息 / 洞府帮助**：查看灵气、灵田概况与玩法说明
- **洞府改名 <名称>**：耗灵石为洞府更名（最长 12 字，每次 10000 灵石）

### 转世气运

- **飞升转世**：满级玩家可转世，重置境界换取转世次数与专属称号
- **我的转世**：查看转世次数、称号
- 转世「气运加身」：转世次数越高，越易参悟天机、突破瓶颈，寻觅机缘时更易获珍稀之物

### 数值与机制重设计

- 修正「化圣境八层」战力笔误（78 亿 → 7.8 亿），化圣境数值恢复线性
- 后期突破率重设梯度（原锁死 1% 改为 12%→2% 递减），失败保底改为固定累加
- 防具减伤整体上浮，法器新增破防属性，战斗防守方更强势
- 装备掉落改为指数衰减加权，高阶装备更难掉落
- 悬赏令结算合并为 `悬赏令结算 [类型]`，新增网络梗任务
- 新增宗门贡献兑换、参悟天机等长线玩法

### 数值显示

- 灵石、修为、气血、真元等**全部以精确整数**展示，不再使用「2.3万」等缩写，且不四舍五入

### 每日重置

- 每日 0 点重置（秘境次数、悬赏刷新、签到等）按 **Asia/Shanghai（UTC+8）** 计算

### 长文本转图片

控制台可配置：

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `longTextToImage` | `false` | 是否启用（开关） |
| `longTextLineThreshold` | `20` | 超过该行数的回复将转为图片（自定义行数） |

基于 Puppeteer 实现（`koishi-plugin-markdown-to-image-service` 内部使用 `@koishijs/plugin-puppeteer` 渲染）。启用后会把任意超过阈值行数的指令回复渲染为**白底深字等宽卡片图片**发出，并已内嵌中文字体，无需额外配置字体；未安装该服务时自动降级为纯文本。

## 开发与测试

本目录为独立插件包 `koishi_plugin_xiuxian`（**不要与 `koishi-app` 根目录的 package.json 混淆**）。

```bash
cd koishi_plugin_xiuxian
npm install
npm run build
npm run test
npm run lint
npm run patch-desc   # 重新生成物品描述（可选）
```

## 发布

```bash
npm run bump -- -3   # 若在 monorepo 内用 yakumo bump
npm run build
npm run pub          # 若在 monorepo 内用 yakumo publish
```
